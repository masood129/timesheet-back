### README.md

این مخزن شامل یک API بک‌اند برای یک اپلیکیشن تایم‌شیت (timesheet) است که با استفاده از Node.js، Express و پایگاه داده MSSQL ساخته شده است. این API مدیریت پروژه‌ها، جزئیات روزانه، گزارش‌های ماهانه و وظایف مرتبط را پشتیبانی می‌کند، با قابلیت محدود کردن دسترسی کاربران به پروژه‌های مجاز.

---

### ویژگی‌ها

- **مدیریت پروژه‌ها**: امکان ایجاد، خواندن (تک و همه)، به‌روزرسانی و حذف پروژه‌ها.
- **مدیریت دسترسی پروژه‌ها**: کاربران تنها به پروژه‌هایی که در جدول `UserProjectAccess` به آن‌ها دسترسی داده شده است، دسترسی دارند.
- **مدیریت جزئیات روزانه**: امکان ایجاد یا به‌روزرسانی جزئیات روزانه برای یک کاربر در یک تاریخ خاص با استفاده از تراکنش‌های اتمی. این جزئیات شامل زمان ورود/خروج، نوع مرخصی، زمان شخصی و هزینه‌ها می‌شود.
- **مدیریت وظایف**: ذخیره‌سازی وظایف روزانه مرتبط با پروژه‌ها.
- **مدیریت هزینه‌ها**: ثبت هزینه‌های شخصی خودرو برای هر روز و پروژه.
- **مدیریت گزارش‌های ماهانه**: ایجاد، ارسال به مدیر، تأیید توسط مدیر و تأیید نهایی توسط تیم مالی با پشتیبانی از نقش‌های مختلف (کاربر، مدیر، تیم مالی).
- **احراز هویت**: ورود کاربران با استفاده از نام کاربری و تولید توکن JWT برای احراز هویت در درخواست‌های بعدی.
- **API مستندسازی شده**: مستندات Swagger برای تمامی endpointها در دسترس است.
- **اتصال به MSSQL**: از کتابخانه `mssql` برای اتصال به پایگاه داده MSSQL استفاده می‌کند.
- **مدیریت زمان**: استفاده از کتابخانه Luxon برای مدیریت تاریخ و زمان با پشتیبانی از منطقه زمانی `Asia/Tehran`.
- **متغیرهای محیطی**: پیکربندی اتصال به پایگاه داده و کلید JWT از طریق فایل `.env` انجام می‌شود که امنیت اطلاعات حساس را تضمین می‌کند.

---

### فناوری‌های استفاده شده

این پروژه از فناوری‌های زیر استفاده می‌کند:

- **Node.js**
- **Express.js**: فریم‌ورک وب برای ساخت API.
- **MSSQL**: درایور برای اتصال به پایگاه داده Microsoft SQL Server.
- **Swagger-UI-Express & Swagger-JSDoc**: برای تولید و نمایش مستندات API.
- **Luxon**: کتابخانه برای مدیریت تاریخ و زمان با پشتیبانی از منطقه زمانی `Asia/Tehran`.
- **jsonwebtoken**: برای احراز هویت مبتنی بر JWT.
- **Dotenv**: برای مدیریت متغیرهای محیطی.
- **CORS**: برای فعال‌سازی Cross-Origin Resource Sharing.

### راه‌اندازی پروژه

#### پیش‌نیازها

مطمئن شوید که موارد زیر روی سیستم شما نصب شده‌اند:

- Node.js (نسخه 18 یا بالاتر)
- Microsoft SQL Server
- نصب وابستگی‌های اضافی:

  ```sh
  npm install jsonwebtoken
  ```

#### ۱. نصب وابستگی‌ها

ابتدا، وارد پوشه پروژه شوید و وابستگی‌های مورد نیاز را نصب کنید:

```sh
npm install
```

#### ۲. پیکربندی پایگاه داده و احراز هویت

فایل `.env` را در ریشه پروژه ایجاد کنید و اطلاعات اتصال به پایگاه داده و کلید JWT را در آن قرار دهید:

```ini
DB_USER=sa
DB_PASSWORD=123@asd
DB_SERVER=localhost
DB_DATABASE=flutter
DB_PORT=1433
JWT_SECRET=your_jwt_secret_key_here
```

**توجه**: این فایل حاوی اطلاعات حساس است و نباید در یک مخزن عمومی Git قرار گیرد. به همین دلیل در فایل `.gitignore` ذکر شده است.

#### ۳. ایجاد جداول پایگاه داده

اسکریپت‌های SQL موجود در فایل‌های `createTable.txt`, `db-schema-additions.sql`, و `create_users_table.sql` را اجرا کنید تا تمامی جداول مورد نیاز (شامل `Projects`, `Users`, `DailyDetails`, `DailyProjectTasks`, `DailyPersonalCarCosts`, `Holidays`, `UserContractHours`, `MonthlyReports`, `MonthlyGymCosts`, و `UserProjectAccess`) و داده‌های نمونه اولیه ایجاد شوند. جدول `Users` شامل ستون‌های `Id`, `Username`, و `Role` است.

#### ۴. اجرای برنامه

با استفاده از nodemon، برنامه را اجرا کنید:

```sh
npm run dev
```

سرور در آدرس `http://localhost:3000` اجرا خواهد شد.

### مستندات API

مستندات کامل API با استفاده از Swagger در دسترس است. پس از اجرای سرور، می‌توانید به آدرس زیر مراجعه کنید:

`http://localhost:3000/api-docs`

این مستندات شامل جزئیات تمامی endpointها و مدل‌های داده‌ای مورد استفاده است.

### مسیرهای API

- `POST /auth/login`: ورود کاربر با استفاده از نام کاربری و دریافت توکن JWT.
- `GET /projects`: دریافت لیست پروژه‌هایی که کاربر فعلی از طریق جدول `UserProjectAccess` به آن‌ها دسترسی دارد.
- `GET /projects/{id}`: دریافت جزئیات یک پروژه خاص، در صورتی که کاربر از طریق جدول `UserProjectAccess` به آن دسترسی داشته باشد.
- `POST /projects`: ایجاد یک پروژه جدید.
- `PUT /projects/{id}`: به‌روزرسانی یک پروژه موجود.
- `DELETE /projects/{id}`: حذف یک پروژه.
- `GET /daily-details/{date}?userId={userId}`: دریافت جزئیات روزانه برای یک تاریخ و کاربر مشخص.
- `GET /daily-details/range?startDate={startDate}&endDate={endDate}&userId={userId}`: دریافت جزئیات روزانه برای یک بازه زمانی.
- `POST /daily-details`: ایجاد یا به‌روزرسانی جزئیات روزانه با استفاده از تراکنش‌های اتمی.
- `GET /daily-details/month/{year}/{month}?userId={userId}`: دریافت جزئیات ماهانه برای یک سال و ماه مشخص.
- `POST /monthly-reports/{year}/{month}`: ایجاد گزارش ماهانه برای کاربر (نیاز به نقش `user`).
- `PUT /monthly-reports/{reportId}/submit-to-manager`: ارسال گزارش به مدیر (نیاز به نقش `user`).
- `PUT /monthly-reports/{reportId}/approve-manager`: تأیید گزارش توسط مدیر و ارسال به تیم مالی (نیاز به نقش `manager`).
- `PUT /monthly-reports/{reportId}/approve-finance`: تأیید نهایی گزارش توسط تیم مالی (نیاز به نقش `finance`).
- `GET /monthly-reports/{reportId}`: دریافت جزئیات گزارش بر اساس شناسه.

### نکات اضافی

1. **مدیریت دسترسی**: برای اطمینان از اینکه کاربران فقط به پروژه‌های مجاز دسترسی دارند، جدول `UserProjectAccess` استفاده شده است. این جدول باید با داده‌های مناسب پر شود (مانند اسکریپت ارائه‌شده در `db-schema-additions.sql`).
2. **احراز هویت و نقش‌ها**: تمامی endpointها (به جز `/auth/login`) نیاز به توکن JWT معتبر دارند که اطلاعات `userId` و `role` را فراهم می‌کند. نقش‌های `user`, `manager`, و `finance` برای endpointهای گزارش‌های ماهانه بررسی می‌شوند.
3. **تراکنش‌های اتمی**: در endpointهای مربوط به جزئیات روزانه، از تراکنش‌ها برای اطمینان از اتمی بودن عملیات (مانند حذف و افزودن وظایف و هزینه‌ها) استفاده شده است.
4. **مدیریت زمان**: تمام تاریخ‌ها و زمان‌ها با استفاده از کتابخانه Luxon و منطقه زمانی `Asia/Tehran` مدیریت می‌شوند.
5. **فرانت‌اند**: اپلیکیشن Flutter باید به‌روزرسانی شود تا از endpoint `/auth/login` برای دریافت توکن استفاده کند، توکن JWT را در هدر `Authorization` ارسال کند و فقط پروژه‌های مجاز را نمایش دهد.

**امنیت**: از آنجا که ورود فقط با نام کاربری انجام می‌شود، توصیه می‌شود مکانیزم‌های امنیتی اضافی (مانند محدودیت IP یا توکن‌های موقت) برای جلوگیری از دسترسی غیرمجاز اضافه شود.
